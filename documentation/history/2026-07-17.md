# 2026-07-17: Two-phase release workflow

## Accomplished

Ported the fixed two-phase release workflow from obsidian-remarkable-sync. The old workflow built and attested artifacts at the triggering commit, then created the version-bump commit and tag — so the build-provenance attestation was bound to a different commit than the release tag, failing community-catalog cryptographic verification. The new design: a "prepare" job (dispatch on a branch) bumps versions, generates CHANGELOG.md, commits, tags (lightweight), then re-dispatches the workflow at the tag; a "publish" job (dispatch-at-tag or tag push) builds, attests (continue-on-error removed), and creates the release with `github.sha` equal to the tag commit. Design proven live on remarkable-sync 1.5.0.

Also updated `scripts/release.sh` workflow description to match the new phases. `bun test` kept in the prepare build gate (388 tests pass). Verbatim copy — repo scripts (`release:update-version`, `release:version-bump`, `release:changelog`) and generated files (including `docs/release-notes.md`) all match.
